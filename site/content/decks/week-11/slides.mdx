<Slide title={"General approaches"}>

<Bullets items={[
  { l: 1, h: "Centroid approach – clusters have “centers” and your assigned cluster is the closest one" },
  { l: 1, h: "Density approach – clusters are concentrations of observations, like cities are densely populated areas" },
  { l: 1, h: "Hierarchical approach – clusters form a hierarchy, like a tree diagram" },
]} />

</Slide>

<Slide title={"Example 1: Anomaly & fraud detection"}>

<Bullets items={[
  { l: 1, h: "We may have some known cases of errors or fraud" },
  { l: 2, h: "Could train a classifier to predict those, look for other similar cases" },
  { l: 1, h: "What about future fraud?" },
  { l: 1, h: "Bad actors are likely always looking to change their tactics, so backward looking methodology may fall short" },
]} />

</Slide>

<Slide title={"Clustering transactions"}>

<Bullets items={[
  { l: 1, h: "What if we clustered transactions on all available transaction characteristics (often, more is better)" },
  { l: 1, h: "Look into outliers, observations that don’t fit" },
  { l: 2, h: "Point anomaly: observation that always stands out" },
  { l: 2, h: "Contextual anomaly: observation that stands out given some context, or expectations" },
  { l: 2, h: "Collective anomaly: collection of observations that stand out because of their relation and characteristics" },
]} />

</Slide>

<Slide title={"Approach to anomaly detection"}>

<Bullets items={[
  { l: 1, h: "Perform clustering to set a “baseline” of normal (or the vast majority) of the data" },
  { l: 1, h: "Determine what “outlier” means given this baseline" },
  { l: 2, h: "Need some measure how far “out” an observation is (e.g., distance from the center of the cluster)" },
  { l: 2, h: "Set a cutoff past which an observation is flagged" },
  { l: 1, h: "Identify outliers, and look into them further (i.e., audit by exception)" },
]} />

</Slide>

<Slide title={"clustering Value Add"}>

<Bullets items={[
  { l: 1, h: "Historically fraud detection was rule based" },
  { l: 2, h: "E.g., low income, high consumption/bank activity" },
  { l: 1, h: "Clustering analyzes lots of variables simultaneously" },
  { l: 1, h: "Identified outliers will have some complex interaction of variables that makes them unlike their peers" },
  { l: 1, h: "Past some set of “rule of thumb” approaches, this kind of high dimensional rule making is hard for humans to do" },
]} />

</Slide>

<Slide title={"What is Dimensionality Reduction?"}>

<Bullets items={[
  { l: 1, h: "Dimensionality reduction collapses many variables into just a few variables that capture the pertinent information" },
  { l: 1, h: "Curse of dimensionality is when too many variables make analysis difficult, computationally infeasible, and more noise than signal" },
]} />

</Slide>

<Slide title={"Accounting is Dimensionality Reduction"}>

  { l: 1, h: "The resultant 10-20 numbers each capture different aspects of the underlying high dimensional data, without losing anything important" },

<Slide title={"PCA Limitations"}>

<Bullets items={[
  { l: 1, h: "PCA is a linear combinations of underlying variables, interpreting that result is not always straight forward" },
  { l: 1, h: "Not using all N components will lose information" },
  { l: 2, h: "Tradeoff # dimensions vs how much information kept" },
  { l: 1, h: "Assumes linearity" },
]} />

</Slide>

<Slide title={"Alternatives to PCA"}>

<Bullets items={[
  { l: 1, h: "t-SNE: non-linear technique for visualization to represent high-dimensional clusters in 2D" },
  { l: 1, h: "UMAP: non-linear technique that preserves the “geometric” structure of high-dimensional data" },
  { l: 1, h: "Generally, non-linear approaches try to model the relationship between data, preserving what’s informative/repeated, dropping the rest" },
]} />

</Slide>
